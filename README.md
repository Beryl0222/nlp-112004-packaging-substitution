# 绿色包装替代时的文本证据与批次承诺

岗桥中转场的班组使用包装试验原文、入库批签与备料清单。数量以一件包裹所需完整组件为单位。站点领料表中的 issued 件仍在线上，直到单据明确记入退回。记录中的试验和供应商均为虚构。

## 本地资料

全部为 UTF-8 编码的合成业务资料。`data/contract.json` 中的列类型带 `?` 时可以是 JSON null。每组记录的 `id` 在该组中唯一，跨组关系以字段说明和清单的 `links` 为准。文字字段保留来源原句，嵌套对象按表中现有格式记录。

- `data/batches.json`。物料批次。component 是部件类，recipe 是配方号。units 为当前实物可领数量。
- `data/reports.json`。试验原文。batchIds 记录送检批签，不单独声明试验结果。revises 为被补记的报告。
- `data/parcels.json`。转运台包裹工况。limitKg 是装载质量。laterUse 为同车班其他限制。
- `data/picklists.json`。班组交接事实。stage 为待领、已领未封、已封、退料在途或已退库。time 为达到此状态的时间。

## 使用约定

批次号是唯一批签，同产品名不能推出同配方。试验如果记录上限而未注明严格小于，等于该值仍属于试验范围。温度和载重允许常规单位换算，操作先后取报告原话。
优先级数值越大越优先。同优先级并列时可以把候选给转运班选择，无须擅自释放已确认物料。实物可领数量为资料所记录时点的货架数量，已领和在途退料均不在其中。按货架实数给已确认且待领的物料留额度。未经质量人员认可的临时配组不具有自动代换权限。

## 读取与检查

使用 Node.js 22.23.4，依赖仅用 Node.js 标准库。资料检查依次读入各组 JSON，检查列类型、组内编号及已登记的组间引用，并列出各组记录数。读取入口为 `tools/materials.mjs`，可单独读取一组记录，或读取整个已登记资料包。

```sh
npm run check-data
npm test
```
